GarnetTouch

A from-scratch touchscreen driver for a phone that was never meant to run Windows.

Ten-finger multitouch in Windows 11 on the Redmi Note 13 Pro 5G, reverse-engineered from the phone's own hardware and the Goodix controller's protocol, with no vendor driver to start from.

How a touch reaches Windows

The signal path

A finger moves charge on the panel. Six hops later, Windows sees a HID contact. Every stage had to be brought up by hand, because nothing in a stock Windows image knows this hardware exists.

The firmware (a small UEFI driver) powers the chip and opens the SMMU gates before Windows boots; the kernel driver owns the DMA engine and speaks the Goodix protocol once Windows is up.

The part that nearly stopped it

The wall was the compiler, not the code

The driver was written and correct. It installed cleanly. And Windows refused to load it — the same cryptic failure every time, with no signature complaint and no log.

The symptom

Rejected before it ran

Every build failed to load with one status code and silence. Not signing, not Memory Integrity, not a missing import — all ruled out one by one. Even a ten-line empty driver was refused.

The cause

An image Windows wouldn't accept

The open-source linker produced an ARM64 kernel image missing the exact Control Flow Guard metadata and thunk section the Windows ARM64 loader requires. Structurally valid everywhere a tool could check, yet the kernel wouldn't take it.

The fix

Build with Microsoft's own toolchain

Rebuilt with the Enterprise WDK. The real compiler emits the metadata the loader expects. The driver loaded on the first try, and touch worked. The code never changed.

The lesson

Trust the evidence, not the hunch

The early guesses (signing, security policy) were wrong. Reading the actual loader behavior and comparing byte-for-byte against a working Microsoft driver is what found it.

For the curious

How it's installed

This is a personal build on a bootloader-unlocked phone, not a public release. The driver is placed into the Windows image offline, from a PC, with the phone in recovery.

  1. Boot the phone into recovery and expose its storage to the PC as a USB drive.
  2. Add the driver to the offline Windows image with DISM /Add-Driver /ForceUnsigned, test-signed with a self-made certificate.
  3. Make sure test signing is enabled in the Windows boot configuration.
  4. Start Windows with the custom UEFI: fastboot boot garnet-uefi.img.
  5. About 20 seconds after the desktop appears, the touchscreen comes alive.

The UEFI brings up touch power, clocks and the SMMU before handing off; the signed kernel driver does the rest once Windows is running.
